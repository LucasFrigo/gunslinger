# Feature Roadmap & Key Concepts: VR Gunslinger Game

Ordered cheapest → costliest for an agent to implement, given what already exists. Cost is the context a turn has to hold, how many live systems a wrong edit breaks, and how many sessions a miss takes. A stronger model plans the upper tiers; a cheaper model implements once that plan is settled. An item that names a dependency stays after it.

**Agent pick** on each item names the model and effort for the plan and the build. Tiers, cheapest first: Haiku 4.5 → Sonnet 5.5 → Opus 5.5 → Fable 5.1. Effort runs `low` → `medium` → `high` → `xhigh` → `max`. Raise effort before you raise the tier. Go up a tier when the work is physics or feel the agent cannot see, or when a wrong edit reaches combat resolve or netcode.

**Living status of what already ships:** `[docs/FEATURES.md](docs/FEATURES.md)` · **How systems work:** `[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)` · **Bugs:** `[docs/BUGS.md](docs/BUGS.md)` · **Pre-release TODOs:** `[docs/RELEASE_TODOS.md](docs/RELEASE_TODOS.md)` · **SFX checklist:** `[docs/SOUND.md](docs/SOUND.md)` · **Shader code:** `[docs/SHADERS.md](docs/SHADERS.md)` · **Design / lore:** `[docs/design/README.md](docs/design/README.md)` · **Versions:** `[CHANGELOG.md](CHANGELOG.md)` / `[VERSION](VERSION)`

When an item below lands (or is clearly underway), update `docs/FEATURES.md`. When it is **done**, move the bullet to **Completed** at the bottom (do not leave strikethrough items in the active lists).

**Ideas** and **Scrapped** (before Completed) are not part of that queue. Those concepts are not ready to build. Add an item there only when asked.

## 1. Low — small context

A cheaper model. One named file, or a catalog entry that already plays. Do not explore the repo.

1. **Replace placeholder SFX:** Combat cues play today via `PlaceholderAudio` except `duel_end.wav`. Check boxes in `[docs/SOUND.md](docs/SOUND.md)` as real files land in `assets/audio/`. Gunshot first. The cost is sourcing the audio, not code. **Agent pick:** Haiku 4.5 to wire each file once it exists.
2. **Height setting calibration:** The VR standing-height setting (see Completed, "VR height calibration") still needs calibrating: the headset-matched height and the torso, legs, and holster offsets do not yet line up for every player height. Test at a few heights (short, average, tall) in a headset and tune the offsets and the calibrate sample. Not a code feature, so the cost is headset time. **Agent pick:** Sonnet 5.5 `medium` once the measurements exist.
3. **VR shot stutter:** *Partly fixed, unmeasured: the reload-status `Label3D` glyphs are pre-rendered, the slug casts no shadow, the per-shot smoke emitters are pooled, and the muzzle light and flash quad are built once per weapon; confirm on Quest (see `docs/RELEASE_TODOS.md`).* In VR duels, each shot causes a slight frame hitch. It feels like the first-use shader compile hitch that an earlier build fixed by caching (warming up) shaders, so a cue or effect fired on a shot is probably missing from the warm-up list (`autoload/impact_feedback.gd`). Reproduce in a headset, then check which shot-time effects (muzzle flash, smoke, shell, impact, decal, sound) are not warmed up; Quest timing confirms the fix. **Agent pick:** Sonnet 5.5 `high` for the diagnosis and fix. Go up to Opus 5.5 if it turns out to be physics or netcode rather than shaders.



## 2. Moderate — one focused session

A mid-tier coding model. The spec is already tight, or another actor already does the thing. Name the files. A stronger model does not earn its keep here.

1. **Photo cells and the sheet builder:** **Route changed (2026-10-18): hand-painted texture per GLB, trim sheet paused.** The user paints one 256×256 image per exported GLB (29 of them, `assets/models/scenarios/<map>/tex/<glb>.png`, ripper output arranged to fit that GLB's own unwrap) instead of building one shared sheet. `dev/unwrap_per_glb_blender.py` gave every GLB fresh non-overlapping UVs and its own materials; the importer shows a GLB's image when it exists and keeps the flat color otherwise. The sheet builder, `dev/trim_layout.py`, the strip UVs' code, and `trim_sheet.png` are kept but unused (`USE_TRIM_SHEET` is false in `world_surface_import.gd`). No texture is painted yet; the art, the texture-ripper trial, and Quest timing remain. Steps: `docs/TEXTURING.md` (Hand-painted texture per GLB). The original plan follows. One-off objects (doors, windows, signs, barrels, crates, a trough, table tops) get a photo of the real thing instead of a strip. Photos are flattened in the texture ripper ([raycastly/texture-ripper](https://github.com/raycastly/texture-ripper), in the browser), kept as one PNG per cell under `assets/texture_src/`, and squashed to 128×128. A new `dev/build_trim_sheet.py` shrinks the strips and cells, cuts them to one shared 32-color palette, pads each cell's border, and writes `assets/textures/trim_sheet.png`. The atlas grows to 512×1024: strips in the top half, 16 cells in a 4×4 grid below. `dev/scenery_uv.py` gains a `CELLS` table, rules from object names to cells (`Door*`, `Win_*`, `Sign`, `Barrel*`, ...), a per-building override file (`bld_bank_door.png`), and a fallback to the strip when a cell is missing; every strip's V halves, so the five unwrap scripts re-run and the 24 GLBs are re-exported. Depends on the trim sheet in game (Completed). Decisions marked "recommended, not confirmed" in `docs/TEXTURING.md` (atlas size, matching rule, seamless strips, palette) are asked first. Try the ripper on one photo and look at one door, window, and wall in the saloon before building more. **Agent pick:** Sonnet 5.5 `high` for plan and build now that the trim sheet shows in game. The art is the cost: the photos, the seamless strips, and the look test. **Started, not done:** the builder (`dev/build_trim_sheet.py`), the 512×1024 atlas, the cell table and name rules, per-building overrides, the manifest fallback, and the GLB re-export are built and tested with no photos. Remaining: the photos and `SOURCES.md` entries, the texture-ripper trial, the look test (decision 6), and Quest timing.

## Ideas

Not ready to build. These stay parked until you ask to mature one into a numbered section above. Add an item here only when asked. This list is not sorted by agent cost.

- **Oil-field smoke plumes (revisit):** Dark smoke heads over the Oil-field Train's burning columns (frame 5 of `docs/design/scenarios/jarhead.jpg`). They were built as `Plume_1` to `Plume_3` meshes in `oilfield_horizon` with the `M_Smoke` distance fog ramp (`assets/shaders/world_smoke.gdshader`; the sheet's F12 and H). They were removed on 2026-10-29: the stacked square lumps read as angular funnels or slabs, and mid-fog plumes read grey. The shader and the belt's lit-anchor hiding stay. Options to weigh when this comes back: rounder 6-sided lumps on a bigger budget, smoke drawn in the flame column's own shader, or a dithered particle head (which sparkles in VR). Judge it against the reference match in `docs/design/scenarios/oilfield_train.md` D.
- **Shootable hat:** The hat is its own volume, separate from the head. A brim hit that misses the skull deals no damage and knocks the hat off along the shot as a rigid body, with a cloth thump. A ray that meets the head is still a headshot (`combat/combat_rules.gd`), and the hat comes off with that hit. The loose hat can be grabbed and seated back on the head (flat look + F, VR off-hand grip), then shot off again. It stays as it was through the death cam. The next standoff puts it on again. Every character that wears one — none do today; the live body is the hatless mannequin (`dummy.glb`). Blocked on the gunslinger outfit being worn in a duel. In 1v1 the host resolves the knockoff and the reseat so both peers agree.
- **More off-hand props:** Extra radial wedges beyond the cigarette, coin, ace, and bottle — badge, etc. Each needs a mesh vendored next to `assets/models/props/msc_cigarette.glb` and an entry in `PropController.ITEMS`; the wheel, attach, and stow plumbing already exist. A peer's avatar already draws the carried prop from the pose stream (`RemoteAvatar._drive_prop`), so a new wedge needs only its `ReplayObjects` / `ReplayBuffer` id. Cigarette polish that is still open: an ember emission / tiny light on the tip, and a readability pass on the thrown cig (real 8.4 cm scale is nearly invisible in flight — see `cig_spin_axis`).
- **More enemy NPCs:** Expand the roster beyond Drunk / Sheriff / Ghost. New opponents are new `ai/archetypes/*.tres` (`AIArchetype` — reaction, accuracy, draw, reload, move style). Wire them into the free-duel pick and gauntlet ladder rungs. Distinct silhouettes/meshes can follow once the gunslinger model is on AI. First design: [Half-head](docs/design/characters/half-head.md).
- **Train Map Concept:** A duel scene featuring a moving train passing between opponents. Players must either wait for the train to clear or attempt risky shots through open train cars. Train Rooftop already scrolls desert and horizon past a stopped train; this item is the train that crosses the lane.
- **Severing (dismemberment):** A killing hit severs the whole head, an arm, or a leg and the piece rides the ragdoll (`characters/body_ragdoll.gd`). Scrapped for now in favor of hit chunks, which only knock a small patch out of the mesh. It would need pre-cut boolean meshes and stumps, keyed off the existing hitboxes. Cosmetic only; `combat/combat_rules.gd` stays as is.
- **Horseback duel stage:** Both duelists fight mounted. Each horse’s speed varies randomly, so relative motion (and the shot window) changes from duel to duel. New arena/scenario; riding locomotion + aim-on-the-move on top of the existing standoff.
- **Ranking & Leaderboard System:** Implement competitive online matchmaking, player ratings, and global/regional leaderboards on **Steam / desktop**. Not on the Meta Store SKU (LAN-only MP).
- **Mod Support:** Provide community modding capabilities (custom gun skins, custom maps, sound packs, and duel scenarios). Plan the loading boundary before any loader; a wrong API is costly to unwind. The plan also has to settle Quest (sideloaded content, store rules), whether mods may ship GDScript, and what the MP version check does with modded clients. **Agent pick:** plan on Fable 5.1 `high` (or Opus 5.5 `max`). Build each loader on Sonnet 5.5 `high` once the boundary is fixed.
- **Campaign Mode:** Develop a narrative-driven or level-based single-player story mode. Highest session count here. The framework stays on a stronger model; a chapter is mid-tier work only after a template exists. **Agent pick:** plan the framework (progression, save, chapter format) on Opus 5.5 `xhigh`. Write chapters on Sonnet 5.5 `medium` once a template chapter exists. Story and lore can draw on `docs/design/`.
