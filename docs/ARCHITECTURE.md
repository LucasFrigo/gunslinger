# Architecture

How major systems fit together. Keep this short; link to files. Update when ownership or flow changes.

Pre-release TODOs: [`RELEASE_TODOS.md`](RELEASE_TODOS.md). SFX checklist: [`SOUND.md`](SOUND.md).

## Runtime stack

- **Engine:** Godot 4.6+/4.7, GDScript, GL Compatibility.
- **XR:** OpenXR + `addons/godot-xr-tools` (hands/pickup toolkit available; core duel loop is custom).
- **Targets:** Quest 3 (Android), PCVR, flat desktop harness (`--flat` or no OpenXR runtime).

## Entry & scene flow

1. `main.tscn` / `main.gd` boots, chooses VR vs flat rig.
2. Boot loading screen (`ui/loading_screen.tscn`) compiles combat AV (`ImpactFeedback.warmup`) while `GameManager` stays in `BOOT`. VR also covers the HMD with a dark quad + status `Label3D`.
3. Main menu (`ui/main_menu.tscn`) landing: Singleplayer / Multiplayer / Tutorial / Practice / Settings / Quit. SP page is gauntlet + free duel; MP page is LAN / Steam host-join. Settings is `ui/settings_menu.tscn`. Menu and flat HUD show `v` + `application/config/version`. `GameManager.go_to_menu()` picks the world behind the menu. **Flat:** it loads a random `SCENARIOS` arena through `_instance_scenario` (which leaves `current_scenario_index` alone for MP) and sets that arena's `process_mode` to disabled. The menu `Background` drops to 20% alpha so the arena shows through. `is_menu_backdrop()` makes `FlatRig` skip movement, gravity, and input. The rig has to stay put because a disabled scene removes its colliders from the space. **VR:** it loads the practice hub, and the floating menu panel spawns there.
4. In-match overlay (`ui/pause_menu.tscn`): ESC / VR menu button. Single-player pauses the scene tree; multiplayer does not (host clock and pose stream keep running). Local fire is suppressed while the overlay is up.
5. `GameManager` loads a scenario (`scenarios/`) and wires player + AI or remote peer.
6. `gauntlet/duel_manager.gd` owns the duel state machine (standoff → bell → draw → resolve).
7. **Tutorial / Practice** calls `GameManager.start_practice()` → `GameMode.PRACTICE`. If the hub is already loaded (VR boot) it just closes the menu; otherwise it tears down and loads `PRACTICE_HUB`. There is no `DuelManager`, AI, or HP (`Player.take_bullet_hit` returns early `in_practice()`). Pause **Reset Range** routes through `reset_current_duel` → `PracticeHub.reset_range()`.

## Combat

- **Weapons:** `WeaponBase` (`RigidBody3D`) → revolver. Visual is `assets/models/weapons/wpn_psx_blaster.glb` instanced as `Model` on `weapons/revolver/revolver.tscn` (pre-cylinder copy: `wpn_psx_blaster_alt.glb`). Greybox `Barrel` / `Cylinder` / `Grip` stay hidden. Live drum is `Model/WPN_PSX_Blaster/CylinderPivot/Cylinder`: gate yaws the pivot, shots index the drum 60°, muzzle kick is visual-only on `Model` so aim markers stay put. Carry states: holstered / held (either hand) / free (simulating). Fire, cock, and reload require `held`; `drawn` stays true while airborne (duel foul / STANDOFF). `attach_to` / `release_into_world` / `holster_to` in `weapons/weapon_base.gd`. Frozen bodies do not inherit parent motion: while `follow_parent` is set, `_sync_follow_parent()` copies the holster or `GunAttach` pose each process/physics frame. VR combat buttons dispatch through `PlayerSettings` binds (`vr_rig.gd`): defaults are gun-hand stick down → cock (edge), A/X → Ocelot spin (hold), B/Y → gate, trigger → fire, grip → hold/toss. Remappable in Settings; conflicts swap. Stick-down on the gun hand steals that stick’s Y from locomotion when bound. Ocelot soft-lock hinges at `SpinPivot`; stick-up (when spin is on stick) or button release relocks. Layer `weapon` (6) vs world when tossed. VR grip is hold-to-hold; toss uses controller linear+angular velocity (plus hinge omega if spinning). Catch either hand or take from the other. `holster_side` (0 right / 1 left, Settings) chooses the hip for draw/holster snap. Off-hand gets belt `ReloadProbe` / `CartridgeAttach` and bump-close. Left B opens debug when that press is not the gun-hand gate bind. Flat: `InputMap` actions `fire` / `draw_toggle` / `cock_hammer` / `reload` rewritten from the same Settings table (defaults LMB / RMB / Space / `R`). Dump/swing in `GameManager.tuning`; **Show reload volumes** on device. Status on `Hud.ReloadStatus` + VR `Label3D`. Flat-only rapid-fire jam: cadence heat in `try_fire` (`jam_enabled` on the local Flat revolver); jammed pull dry-clicks and does not fire; clear by looking down and holding `cock_hammer` (`jam_clear_hold` / `jam_clear_pitch`). VR and AI never jam.
- **Off-hand props:** `PropController` (`props/prop_controller.gd`) is created by `Player._ready` and owns the equip radial plus the equipped prop. Rigs supply everything harness-specific — `get_prop_attach(hand)`, `get_mouth_attach()`, `set_prop_radial_active(active, hand)`, `get_prop_radial_vector()` — so equip / launch / catch is one code path. **Radial:** hold `prop_radial` (VR `primary_click`, honored only on the off hand; flat Tab), highlight with that stick or the mouse, release to equip. `PropController.highlight_index()` maps the vector to a wedge, with a centre deadzone that cancels. VR draws `Label3D` wedges on the hand (`props/prop_radial.gd`, kept square to the HMD) and steals that stick from move/turn in `vr_rig.gd`; flat draws a 2D wheel (`ui/prop_radial_overlay.gd` on `Hud`) and freezes look while it is held. Wedges are **Empty Hand** and **Cigarette**; the wheel refuses to open mid-flight or while a belt round is in hand. **Boomerang:** `props/cigarette.gd` is a plain `Node3D` (no collision, so it cannot block `ReloadProbe` / belt) with states `HELD → CHARGING → OUTBOUND → HOVERING → RETURNING`. Pressing the throw button starts the windup: `_wind_up()` rewrites the local transform each frame (draw-back plus wrist cock) and fills `_charge` over `cig_charge_time`. Release re-parents it to `get_tree().current_scene`, fixes `_direction` to controller `-Z` (VR) or camera forward (flat) **once**, and sets the turnaround to `lerp(cig_min_range, cig_max_range, charge)` — so flight is a straight line unless `cig_curve` bends it. `HOVERING` then burns `cig_flight_time - 2 * range / cig_speed` (computed once at release, floored at zero) parked at the far end, which is what keeps a tap and a full-charge throw the same length; after that it homes to the attach and re-parents inside `cig_catch_radius`. The flick spin snaps on at launch and only stops on catch; `cig_spin_axis` picks sweeping it around its middle like a thrown baton (1, the default — the mesh is too symmetric for a roll to read) or rolling around the tube (0). `cancel_charge()` drops a windup on pause or death. Mesh orientation: the attach basis maps the cig's +Y so the filter faces the player, which is why `PropAttach` / `MouthAttach` carry a 90° X rotation rather than identity. `_update_prop_attach` re-seats the prop when the revolver changes hands and parks it on the VR camera `MouthAttach` while a belt cartridge is held.
- **Bullets:** Real projectiles (`weapons/bullet.gd`), not hitscan; feed trails; near-miss check vs player head; world/body impact feedback on ray hit. Player/peer shots keep shooter hitbox RIDs but ignore only the **gun-hand arm** inside `self_hit_grace` of the muzzle so a forward shot does not clip the forearm; torso / head / off-hand / legs can be hit immediately (muzzle into body). Arm volumes are limb capsules with wrist inset (`Hitbox.place_along_limb` on the local player and remote avatar). AI bullets keep a full self-exclude.
- **Damage:** Host-authoritative in MP. Hits apply only while `DuelManager.accepts_hits()` (state `DRAW`); `Hitbox.receive_hit` and `mp_report_hit` no-op in `IDLE` / standoff / wait-for-bell / `RESOLUTION`, so a post-foul shot cannot overwrite a DQ. `CombatRules` (`combat/combat_rules.gd`): head always kills; torso/arm/leg subtract `Hitbox.damage_mult` HP (default player HP 2). Surviving arm hits fling the held revolver upward (`WeaponBase.pain_jerk_into_world`); there is no redraw lock — VR catches with either hand, flat looks at the loose gun and presses draw. AI tosses the same way and snatches the gun back after `arm_disarm_duration`. Leg hits apply a timed move-speed penalty. A self-kill loses the duel (SP reason `You shot yourself`). Non-fatal MP wounds sync via `DuelManager._mp_wound`. `Hitbox.region` also drives AV. `_finish_sp` is idempotent once `RESOLUTION` is set.
- **Feedback:** `ImpactFeedback` autoload — spatial SFX (`assets/audio/`, swap via `AudioCatalog`), one-shot particles (`assets/vfx/`), XR rumble + flat joy vibration (`assets/haptics/`). Cue checklist and placeholder vs real status: [`SOUND.md`](SOUND.md). `GameManager.setup` shows `ui/loading_screen.tscn` (and a VR HMD cover) and awaits `warmup()` before `go_to_menu()`. That precaches audio PCM and draws a tiny, camera-parented copy of muzzle/impact particles, the trail ribbon, the slug mesh, and a muted gunshot so the first live round does not compile those pipelines.
- **Kill cam:** `DuelManager.kill_cam_requested(trail_points)` → `KillCam` (SP and 1v1 MP). Flat: cinematic fly-along `Camera3D`. VR: spectator `XROrigin3D` ride (player rig stays put) + `XRToolsFade`. `TimeManager.notify_kill_cam` burst allowed in MP; other slow-mo stays SP. Lethal sting: `AudioCatalog` `&"duel_end"` on `notify_kill_shot`.

## AI

- Data-driven `AIArchetype` resources (reaction, accuracy cone, draw speed, `reload_time`, movement).
- After 6 shots the AI enters `RELOADING`: gate opens (cylinder tilt), arm dips, waits `reload_time / ai_speed_mult`, then `WeaponBase.fill_cylinder()` + `close_gate()` and resumes fire. Arm hit / death / duel-over close the gate without refilling. SP only.
- SP spawn: `GameManager._begin_ai_duel` instantiates `ai/duelist.tscn`, assigns `ScenarioBase.get_enemy_spawn()`, then `DuelistAI.capture_spawn()` (`global_position`). Do not snapshot position in `_ready` — that runs at packed-scene origin before placement. Sheriff/Ghost strafe around that captured origin; Drunk stands.
- Encounter ladder: `DuelEncounter` + `GauntletLadder` `.tres` files — prefer data over code for new rungs.

## Multiplayer

- Interface in `netcode/`; `enet_transport.gd` (LAN + UDP discovery), `steam_transport.gd` (optional GodotSteam GDExtension).
- **SKU split:** Meta Store / Quest APK is **LAN-only**. Steam lobbies are desktop / Steam. `NetworkManager.steam_available()` is false on Android; `ui/main_menu.gd` hides Steam host/join chrome there. No Meta dedicated-server path.
- **Steam 1v1:** `NetworkManager` inits Steam once on desktop (`steamInitEx` app ID 480, then `initRelayNetworkAccess`). GodotSteam 4.22 lives in `addons/godotsteam/` (not enabled as an editor plugin; the GDExtension loads on its own). `steam_appid.txt` + Project Settings `steam/initialization/app_id` are 480 for editor/dev; `addons/gunslinger_steam_export/` copies that file next to Windows/Linux/macOS executables. Lobby metadata: `gunslinger=1`, display name, `gunslinger_version`. Browse uses worldwide distance + that game key. Join refuses when lobby version ≠ local `application/config/version` (before `SteamMultiplayerPeer`); mismatched lobbies stay listed but disabled. `SteamMultiplayerPeer` is created with `server_relay`. Host session starts on `lobby_ready`; joiner waits until the Godot peer is `CONNECTION_CONNECTED`, then completes a version hello RPC before `session_started`. Steam invite overlay is not auto-opened on host (that stole the HOST click and stuck the dialog); pause **Invite friends** calls `activateGameOverlayInviteDialog`. Full lobby (2/2) is set unjoinable until the peer leaves. **Virtual ports rotate:** GodotSteam 4.22's `SteamMultiplayerPeer.close()` never frees its P2P listen socket, so a port is spent for the life of the process. Sessions therefore use `create_host(port)` / `create_client(owner, port)` with a port `SteamTransport._spent_virtual_ports` has not seen (0 first, then random 1–999) and the host publishes it as lobby metadata `gunslinger_port`; do **not** go back to `host_with_lobby` / `connect_to_lobby`, which hardcode port 0 and break every session after the first ([BUG-009](BUGS.md)). Because those helpers are bypassed the addon's `tracked_lobby` is unset, so `SteamTransport` handles `lobby_chat_update` itself to drop the peer when the other player leaves. Create and join are one in-flight request issued from `poll()`: a lobby arriving after the player left is left again instead of adopted, and an unanswered request fails after 10s. `close()` drops the Godot peer before leaving the lobby, and `NetworkManager.leave()` always tears the long-lived Steam transport down even when `transport` is already nuler; it does not shut Steam down. Overlay invite on host is best-effort (`activateGameOverlayInviteDialog`).
- LAN discovery (`lan_discovery.gd`): host beacon on UDP 9100 answers pings and announces `ip|name|version` on `255.255.255.255` plus subnet `.255` (legacy `ip|name` / bare name still parse with empty version). Browse list disables incompatible hosts; `join_lan` refuses when the discovery cache has a mismatched version. Typed IP with no beacon metadata relies on the handshake. Gameplay ENet is UDP 9099, bound to IPv4 `0.0.0.0`.
- **MP version handshake:** After ENet/Steam connect, the joiner sends `_version_hello`; the host does not emit `peer_joined` (and thus does not start the duel) until versions match. Mismatch → reject RPC with both strings, disconnect joiner, host session stays up. ~3s timeout treats a silent peer as an older build.
- Quest Android export: `addons/gunslinger_lan_permissions/` injects `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, and `CHANGE_WIFI_MULTICAST_STATE` into the manifest at gradle export (also set on `export_presets.cfg`). Without `INTERNET`, `create_server` fails with "Can't create" on device. Steam Link + editor is Windows networking, not the APK. GodotSteam is excluded from the Android preset (`exclude_filter`).
- Pose / shot sync; host validates hits and HP; non-fatal wounds via `_mp_wound`; auto rematch. Gameplay slow-mo off while networked; kill-cam burst still plays after `RESOLUTION` from `_mp_finish` trail points. Pose RPC is `head, left, right, flags, gun_transform`. Flags: `GUN_DRAWN`, `GUN_COCKED`, `GUN_FREE`, `HOLSTER_LEFT`, `GUN_HELD_LEFT`, `GUN_SPINNING`. Remote interpolates a free or spinning gun; does not simulate physics.
- `RemoteAvatar` (`player/remote_avatar.tscn`): pose-driven head/hands plus torso/leg meshes and shoulder-to-hand arms. Revolver sits on the chosen hip until drawn, parents to left or right hand (identity, or interpolated world pose while `GUN_SPINNING`), or follows the free-gun transform.
- MP spawn: host on `PlayerSpawn`, joiner on `EnemySpawn`. `reset_for_duel` copies the marker transform onto the Player root. Flat look yaw is stored local to that root (do not apply marker yaw twice). VR `reset_locomotion` yaws the origin so the HMD faces the marker -Z. Flat walk and VR stick locomotion apply in world XZ (`global_position`) from look yaw so the joiner's 180° root does not invert strafe.

## Voice chat

- **Buses:** `assets/audio/default_bus_layout.tres` (project setting `audio/buses/default_bus_layout`) adds **Voice** (incoming peer, own volume slider) and **Mic** next to the existing **Master**. `Mic` is **muted** and carries an `AudioEffectCapture` — muting a bus still feeds its effects, and it is what keeps players from hearing themselves. `audio/driver/enable_input=true` is required or the mic never opens. `PlayerSettings.apply_audio()` drives Master + Voice; everything else still defaults to Master, so existing SFX are untouched.
- **Capture:** `VoiceChat` (`autoload/voice_chat.gd`) owns one `AudioStreamPlayer` with an `AudioStreamMicrophone` on the `Mic` bus. It only runs while a session is live **or** Settings is on screen (`add_monitor` / `remove_monitor` refcount, so the mic is not held open for the whole process just to draw a level bar). `is_available()` is a pure query (headless / `Dummy` driver / missing bus / ungranted Android permission) — it never prompts, because the UI and debug panel poll it.
- **Codec:** driver-rate stereo frames are downmixed and box-averaged to **16 kHz mono PCM16**, 320 samples (20 ms, 640 B) per packet, then a one-pole **180 Hz high-pass** (rumble / fan thump) and a squared-ratio expander below the noise-gate cutoff. Cheap: one extra multiply per 16 kHz sample.
- **Gating:** mute always wins. With push-to-talk **on**, the bind is the whole gate (the expander still ducks room tone while you hold it). With it **off**, RMS must clear Settings **Noise Gate** (`PlayerSettings.voice_gate_cutoff`, default 0.08, same units as the mic-level bar) plus a 0.18 s hang so word tails survive. 0 disables the gate. Raise the slider until the bar sits still when you are quiet.
- **Latency:** capture discards everything but the newest 40 ms after a hitch (WASAPI can otherwise dump seconds of backlog). Incoming packets sit in a 2-deep queue that drops the oldest on overflow, and playback is capped around 40–80 ms. `_voice` is `@rpc(..., "unreliable", 2)` and `_voice_state` uses channel 1, so a reliable shot on channel 0 cannot stall the mic for seconds. ENet's default `channel_count` is already 3 (0..2).
- **Spatial playback + mute X:** `RemoteAvatar/Head/MouthMarker` holds `VoicePlayer` (`AudioStreamPlayer3D`, `Voice` bus, `voice_max_distance` / `voice_unit_size` from `GameManager.tuning`) and `MuteX` (billboard `Label3D`). `GameManager._spawn_avatar` / `_despawn_avatar` call `VoiceChat.bind_voice_player()`. Mute state travels on pose flag `POSE_FLAG_VOICE_MUTED` (30 Hz steady state) plus a reliable `_voice_state` RPC that covers the gap between `peer_joined` and the first pose; both land on `RemoteAvatar.set_voice_muted()`.
- **Binds:** flat `voice_mute` (**M**) and `voice_ptt` (**V**) are ordinary `FLAT_ACTIONS` rows, so they remap and persist like combat keys. VR is deliberately **not** in the bind table: all six `VR_SOURCES` are already combat binds, so a VR voice bind could only be bought by unbinding a combat button. VR is always-on plus the Settings mute toggle.
- **Quest:** `RECORD_AUDIO` is injected by `addons/gunslinger_lan_permissions/` (the export dialog rewrites the checkboxes, same reason as `INTERNET`). `VoiceChat` calls `OS.request_permissions()` once and retries capture every second, so granting the prompt mid-session starts voice without a restart.

## Config / user data

Persisted under `user://`: `settings.cfg` (volume, voice volume / mute / push-to-talk / noise-gate cutoff, audio input+output device names, flat window/resolution, VR/flat combat binds), `slowmo.cfg`, `movement.cfg`, `tuning.cfg`, `debug_presets.cfg`. A saved audio device that is no longer present falls back to `Default` and the config is rewritten.

Build identity is `VERSION` (mirrored in `project.godot` → `application/config/version`). `python dev/bump_version.py patch|minor` updates both; pushes to `main` that change code also auto-bump via `.github/workflows/bump-version.yml` if `VERSION` was not already updated.

## Menus / pause

- Main menu and pause share `ui/settings_menu.tscn` (scrollable; Controls remapping). Back from Settings (or Esc) returns to the landing page or the pause root. Esc on the SP / MP pages also returns to landing.
- `Hud` (`PROCESS_MODE_ALWAYS`) owns both Controls. VR reparents them into a world `UIPanel3D` (`Player.show_menu_panel`); `reclaim_menu` returns each to `MenuHolder` / `PauseHolder`.
- SP pause: `get_tree().paused`. `TimeManager` / `KillCam` skip ticks while paused. `VRRig` stays `PROCESS_MODE_ALWAYS` so the laser can hit the overlay; locomotion is skipped while paused or the overlay is open.
- MP overlay: title **Menu**, tree not paused, restart disabled for clients. Quit calls `GameManager.go_to_menu()` (`NetworkManager.leave()`).
- Flat ESC toggles pause in-match; on a main-menu sub-page (SP, MP, Settings) it goes Back first. VR left menu/Y opens pause in-match and still opens debug on the main menu. F3 stays debug.

- Canyon: `dev/build_canyon_blender.py` → `assets/models/scenarios/canyon/canyon.glb` (+ `canyon.blend` with `importer="keep"`). West and east cliffs are overlapping segments whose inner face wanders along the wash (the west face is the lighter rock), so the corridor bends instead of running as two straight walls. Rock cover is off the centerline. The top is a narrow butte: a sheer face falls about 24 m on every side (no stepped slope). An invisible rim keeps you on the rock. Below that, a desert plain carries cacti, scrub, and distant mesas. The plain is 6 km across. Depth fog on the canyon `WorldEnvironment` stays clear through the duel and is fully opaque by 220 m, and the sky ground matches that fog so the border does not draw a line. The sun's shadow distance is 360 m and starts fading at 35% so the cascade does not cut a seam in front of the distant mesas. That horizon dressing has no collision. The build refuses any `-convcolonly` proxy in the shot lane (`|x| < 1.6`, `|z| < 12`, height 0.9–1.9) or on a spawn pad. `PlayerSpawn` / `EnemySpawn` and `duel_distance` 22 stay. Faces are kept off the same plane so the cliffs do not flicker.
- Random time of day: `scenarios/time_of_day.gd` samples dawn → noon → late afternoon → dusk. `GameManager._load_scenario` rolls `t` for single-player and the menu; the host sends that `t` on `DuelManager._mp_begin` so both peers match. `ScenarioBase.apply_time` keeps each map’s sun yaw and only changes elevation, sky colors, light color/energy, and fog sun-scatter. It copies `fog_light_color` from `ground_horizon_color` and leaves fog mode, density, depth begin/end/curve, aerial perspective, sky affect, sky/ground curves, and directional shadow distance/fade/splits on the scene — those are what hide Canyon’s plain and the Train Rooftop belt wrap. No `Sun` node (Saloon) skips the pass. F3 `time_of_day` scrubs the live arena.

The model carries `BottleSpot*` and `SlotSpot` empties; `PracticeHub._ready` spawns a `PracticeBottle` on each spot and the `SlotMachine` on the porch. The hub has no `EnemySpawn` (`ScenarioBase` only asserts `PlayerSpawn`; `get_enemy_spawn()` asserts on use).

## Practice hub

- **Ownership:** `PracticeHub` (`scenarios/practice_hub/practice_hub.gd`, extends `ScenarioBase`) owns the bottles, the broken counter (scoreboard `Label3D` + `Hud.set_practice_count`), `reset_range()`, and the bottle lookup (`nearest_bottle`, `bottle_along_ray` with a world-occlusion check). `GameManager.practice_hub()` / `in_practice()` expose it.
- **Bottles:** `practice/practice_bottle.gd` (`RigidBody3D`, layer 7 `practice_prop`). States: `HOME` (static frozen on its spot, mask 0), `HELD` (mesh parented to the hand so it does not stutter; body stays on layer 7 with mask 0, so a shot still shatters it and it does not push the player), `LOOSE` (simulating, mask world + props), `BROKEN` (hidden, body disabled, 2 s timer → `go_home`). `take_bullet` or a contact at ≥ `BREAK_SPEED` (pre-contact speed) calls `shatter`, which also breaks another bottle it hits. Body-state changes inside contact callbacks are deferred. Lost bottles (fell below -10 m or 80 m away) go home without counting. Bottles never sit on layer 1, so they cannot block the player capsule or `ReloadProbe`.
- **Bullets:** `weapons/bullet.gd` `HIT_MASK` includes layer 7; any collider with `take_bullet(point, dir)` gets called instead of the world impact.
- **Grab / throw:** `Player` owns `_held_bottle`. VR: off-hand grip (after gun catch and holster draw, before the belt) grabs within `max(gun_catch_radius, 0.2)`. Only an empty off hand can grab: no prop, cartridge, or bottle. Release throws with hand velocity and spin scaled by the gun toss tunings. Flat: `interact` (F) raycasts 2.5 m from the camera onto `FlatRig/BottleAttach`, and F again throws along aim. `PropController` refuses the radial and throws while a bottle is held. `reset_for_duel` drops the bottle.
- **Slot machine:** `practice/slot_machine.gd` (`StaticBody3D` on layer 1, front faces local +Z). `pull()` returns false while spinning. Reels tick `SYMBOLS` and stop at `REEL_STOPS`. The result is rolled on pull (`WIN_CHANCE` 12% for three of a kind, otherwise a guaranteed miss). A win flashes the topper and plays `ImpactFeedback.slot_win` (coin burst + sting). VR: trigger with the hand within `LEVER_REACH` of the lever segment pulls it and does not fire. Flat: F while `is_looked_at` hits the cabinet.
- **AV:** VFX `glass_shatter` / `coin_burst` in `VfxCatalog`; placeholder cues `glass_break`, `slot_pull`, `slot_stop`, `slot_win` in `AudioCatalog` / `PlaceholderAudio`.
