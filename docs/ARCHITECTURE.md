# Architecture

How major systems fit together. Keep this short; link to files. Update when ownership or flow changes.

Pre-release TODOs: [`RELEASE_TODOS.md`](RELEASE_TODOS.md). SFX checklist: [`SOUND.md`](SOUND.md).

## Runtime stack

- **Engine:** Godot 4.6+/4.7, GDScript, GL Compatibility.
- **XR:** OpenXR + `addons/godot-xr-tools` (hands/pickup toolkit available; core duel loop is custom).
- **Targets:** Quest 3 (Android), PCVR, flat desktop harness (`--flat` or no OpenXR runtime).

## Entry & scene flow

1. `main.tscn` / `main.gd` boots, chooses VR vs flat rig.
2. Boot loading screen (`ui/loading_screen.tscn`) compiles combat AV (`ImpactFeedback.warmup`) while `GameManager` stays in `BOOT`. VR also covers the HMD with a dark quad + status `Label3D`.
3. Main menu (`ui/main_menu.tscn`) landing: Singleplayer / Multiplayer / Tutorial / Practice / Settings / Quit. SP page is a mode list (Gauntlet / Single Duel / Horde), each opening its own page (`GauntletPage` / `DuelPage` / `HordePage`) with a blurb, pickers, best record, and START; `GauntletController._victory/_defeat` call `PlayerSettings.record_gauntlet_run`. MP page is LAN / Steam host-join. Settings is `ui/settings_menu.tscn`. Menu and flat HUD show `v` + `application/config/version`. `GameManager.go_to_menu()` picks the world behind the menu. **Flat:** it loads a random `SCENARIOS` arena through `_instance_scenario` (which leaves `current_scenario_index` alone for MP) and sets that arena's `process_mode` to disabled. The menu `Background` drops to 20% alpha so the arena shows through. `is_menu_backdrop()` makes `FlatRig` skip movement, gravity, and input. The rig has to stay put because a disabled scene removes its colliders from the space. **VR:** it loads the practice hub, and the floating menu panel spawns there.
4. In-match overlay (`ui/pause_menu.tscn`): ESC / VR draw-hand stick click (`pause`, rebindable; shares the click with the off-hand prop wheel). Single-player pauses the scene tree; multiplayer does not (host clock and pose stream keep running). Local fire is suppressed while the overlay is up.
5. `GameManager` loads a scenario (`scenarios/`) and wires player + AI or remote peer.
6. `gauntlet/duel_manager.gd` owns the duel state machine (standoff → bell → draw → resolve).
7. **Tutorial / Practice** calls `GameManager.start_practice()` → `GameMode.PRACTICE`. If the hub is already loaded (VR boot) it just closes the menu; otherwise it tears down and loads `PRACTICE_HUB`. There is no `DuelManager`, AI, or HP (`Player.take_bullet_hit` returns early `in_practice()`). Pause **Reset Range** routes through `reset_current_duel` → `PracticeHub.reset_range()`.
8. **Mesh lab** (F3 only, `GameMode.MESH_LAB`, `dev/mesh_lab/`) is a debug stage, not a duel arena. Entering drops the duel, gauntlet, and network session the same way as the main menu. **Flat:** the local player is parked and a `MeshLabPuppet` walks a circle with random head and hand targets through `DummyBody`. A fly `Camera3D` (WASD along the look, mouse look) is current. **VR:** the headset player stays on the real rig. A second `Window` + `SubViewport` shares the lab world so the desktop can fly around them. Body and head render on layer 20, which the XR camera skips, so the headset stays first person and the desktop sees the full mesh. Checkboxes on the flat view and on that desktop window (`MeshLabMotion`) freeze head, walk, or hands independently. Leaving always calls `go_to_menu()`.

## Combat

- **Weapons:** `WeaponBase` (`RigidBody3D`) → revolver. Visual is `assets/models/weapons/wpn_psx_blaster.glb` instanced as `Model` on `weapons/revolver/revolver.tscn` (pre-cylinder copy: `wpn_psx_blaster_alt.glb`). Greybox `Barrel` / `Cylinder` / `Grip` stay hidden. Live drum is `Model/WPN_PSX_Blaster/CylinderPivot/Cylinder`: gate rolls the pivot out to the side and down on a bore hinge (mirrored for `shooting_hand`), shots index the drum 60°, muzzle kick is visual-only on `Model` so aim markers stay put. Carry states: holstered / held (either hand) / free (simulating). Fire, cock, and reload require `held`; `drawn` stays true while airborne (duel foul / STANDOFF). `attach_to` / `release_into_world` / `holster_to` in `weapons/weapon_base.gd`. A toss off a running hinge spin sets `carrying_spin` and keeps the turn rate on the rigid body; `attach_to` on the next catch (any hand, before the first bounce) restarts the hinge on that hand's X axis at the body's turn rate. Arm-hit tosses pass `keep_hinge := false`. Frozen bodies do not inherit parent motion: while `follow_parent` is set, `_sync_follow_parent()` copies the holster or `GunAttach` pose each process/physics frame. On the local VR revolver (`use_aim_steady`), a held gun instead damps slow wrist rotation and keeps its origin on `GunAttach`; the trigger frame holds the previous bore. Strength 0, flat, AI, spin, and toss copy or bypass as before. The controller hand stays raw. VR combat buttons dispatch through `PlayerSettings` binds (`vr_rig.gd`): defaults are gun-hand stick down → cock (edge), A/X → Ocelot spin (hold), B/Y → gate, trigger → fire, grip → hold/toss. Remappable in Settings; conflicts swap. Stick-down on the gun hand steals that stick’s Y from locomotion when bound. Ocelot soft-lock hinges at `SpinPivot`. Pressing the bind applies `spin_start_boost` so the muzzle tip moves upward. While the hinge is still slow, wrist coupling stays low and hand acceleration torques the barrel from its center of mass, so the spin starts with the motion; full coupling returns once it is turning. Stick-up (when spin is on stick) or button release relocks. Layer `weapon` (6) vs world when tossed. VR grip is hold-to-hold; toss uses controller linear+angular velocity (plus hinge omega if spinning). Catch either hand or take from the other. `holster_side` (0 right / 1 left, Settings) chooses the hip and the default draw hand (flat RMB, the holstered pause stick, and which hand is the off hand for props and reload). Either hand can still grab the hip in VR. Gun-hand stick click opens pause (`PlayerSettings` `pause`, same click as the off-hand prop wheel). Off-hand gets belt `ReloadProbe` / `CartridgeAttach` and bump-close. Flat: `InputMap` actions `fire` / `draw_toggle` / `cock_hammer` / `reload` rewritten from the same Settings table (defaults LMB / RMB / Space / `R`). Dump/swing in `GameManager.tuning`; **Show reload volumes** on device. Status on `Hud.ReloadStatus` + VR `Label3D`. Flat-only rapid-fire jam: cadence heat in `try_fire` (`jam_enabled` on the local Flat revolver); jammed pull dry-clicks and does not fire; clear by looking down and holding `cock_hammer` (`jam_clear_hold` / `jam_clear_pitch`). VR and AI never jam.
- **Off-hand props:** `PropController` (`props/prop_controller.gd`) is created by `Player._ready` and owns the equip radial plus the equipped prop. Rigs supply everything harness-specific — `get_prop_attach(hand)`, `get_mouth_attach()`, `set_prop_radial_active(active, hand)`, `get_prop_radial_vector()` — so equip / launch / catch is one code path. **Radial:** hold `prop_radial` (VR `primary_click`, honored only on the off hand; flat Tab), highlight with that stick or the mouse, release to equip. `PropController.highlight_index()` maps the vector to a wedge, with a centre deadzone that cancels. VR draws `Label3D` wedges on the hand (`props/prop_radial.gd`, kept square to the HMD) and steals that stick from move/turn in `vr_rig.gd`; flat draws a 2D wheel (`ui/prop_radial_overlay.gd` on `Hud`) and freezes look while it is held. Wedges are **Empty Hand**, **Cigarette**, **Coin**, **Ace of Spades**, and **Bottle**; the wheel refuses to open mid-flight or while a belt round is in hand. Equipped props implement `OffhandProp` (`props/offhand_prop.gd`). **Flight query:** `props/prop_flight.gd` raycasts each outbound and return step against world + `practice_prop`; a `PracticeBottle` or off-hand `Longneck` shatters, any other solid is a wall on the way out. Held meshes stay shapeless. **Boomerang:** `props/cigarette.gd` is a plain `Node3D` (no collision, so it cannot block `ReloadProbe` / belt) with states `HELD → CHARGING → OUTBOUND → HOVERING → RETURNING`. A wall or bottle on `OUTBOUND` skips `HOVERING` and homes; a bottle on `RETURNING` shatters and the cig keeps coming. **Coin:** `props/coin.gd` is a `RigidBody3D` that stays shapeless while held. Flat **G** flips on press and picks heads or tails for the catch (`_toss_face`, odd/even half-turns) so it does not always reseat tails-up; a miss rests on the floor and pickup reads the world face. A short catch grace stops it reseating on the same tap. VR still drops it if the palm tilts. **Ace:** `props/ace.gd` charge-throws then simulates as a `RigidBody3D` so it can be picked up (flat F / VR off-hand grip). Practice hub `_align_ground_collision` disables the imported lot-height Ground pad and adds `LotPad` / `DesertPad` so a thrown card sits on the lot or the sand, not in mid-air; `PropFlight.snap_out_of_ground` lifts a tunneled body back onto the hit. **Bottle:** `props/bottle.gd` (`Longneck`) is the same charge-throw and pickup, using `msc_longneck.glb` on layer 7 so a held or loose bottle still takes a bullet. Local `HOLD` is +90° around X so the neck stands up in `PropAttach` (that node aims child +Y forward for the cigarette). A hard impact (≥ `PracticeBottle.BREAK_SPEED`) or `take_bullet` plays `glass_shatter` and frees the instance — no rail home. `PropFlight.shatter_body` is the shared glass check so a cig, ace, coin, or rail bottle can break a longneck and the other way around. Reselecting a radial wedge always despawns the previous instance. Pressing the throw button starts the windup: `_wind_up_pose()` rewrites the local transform each frame (draw-back plus wrist cock) and fills `_charge` over `cig_charge_time`. Release re-parents it to `get_tree().current_scene`, fixes `_direction` to controller `-Z` (VR) or camera forward (flat) **once**, and sets the turnaround to `lerp(cig_min_range, cig_max_range, charge)` — so flight is a straight line unless `cig_curve` bends it. `HOVERING` then burns `cig_flight_time - 2 * range / cig_speed` (computed once at release, floored at zero) parked at the far end, which is what keeps a tap and a full-charge throw the same length; after that it homes to the attach and re-parents inside `cig_catch_radius`. The flick spin snaps on at launch and only stops on catch; `cig_spin_axis` picks sweeping it around its middle like a thrown baton (1, the default — the mesh is too symmetric for a roll to read) or rolling around the tube (0). `cancel_charge()` drops a windup on pause or death. Mesh orientation: the attach basis maps the cig's +Y so the filter faces the player, which is why `PropAttach` / `MouthAttach` carry a 90° X rotation rather than identity. `_update_prop_attach` re-seats the prop when the revolver changes hands and parks it on the VR camera `MouthAttach` while a belt cartridge is held.
- **Bullets:** Real projectiles (`weapons/bullet.gd`), not hitscan; feed trails; near-miss check vs player head; world/body impact feedback on ray hit. Player/peer shots keep shooter hitbox RIDs but ignore only the **gun-hand arm** inside `self_hit_grace` of the muzzle so a forward shot does not clip the forearm; torso / head / off-hand / legs can be hit immediately (muzzle into body). Hit volumes are capsules on the posed mannequin bones (`characters/body_hitboxes.gd`); the gun-hand forearm is thinner and stops short of the wrist. AI bullets keep a full self-exclude.
- **Damage:** Host-authoritative in MP. Hits apply only while `DuelManager.accepts_hits()` (state `DRAW`); `mp_report_hit` no-ops otherwise, and `Hitbox.receive_hit` asks `DuelManager.accepts_hit(victim, shooter)`, which is `accepts_hits()` plus one exception: an NPC shot by another NPC (`shooter >= 1`) while `survivors_fighting()` (after a loss, on the trailing orbit). A post-foul shot still cannot overwrite a DQ. `Bullet.spawn(..., shooter)` carries a ReplayBuffer actor id through `Hitbox.receive_hit` to the owner's `take_bullet_hit(..., shooter)` (the local player passes its replay id, an NPC its `actor_id`; a peer's shot spawned from the network passes -1); it sets `DuelistAI.killed_by` / `Player.killed_by` for kill credit. `Hitbox.is_corpse()` (a dead NPC, or the local player after an SP death) makes `Bullet` pass through those volumes (`MAX_PASS_THROUGH` skips per step), so corpses do not soak shots meant for the duelists still standing. NPC revolvers carry `shooting_hand = &""`, so their shots never pulse the player's controller ([BUG-017](BUGS.md)). `CombatRules` (`combat/combat_rules.gd`): head always kills; torso/arm/leg subtract `Hitbox.damage_mult` HP (default player HP 2). Surviving arm hits fling the held revolver upward (`WeaponBase.pain_jerk_into_world`); there is no redraw lock — VR catches with either hand, flat looks at the loose gun and presses draw. AI tosses the same way and snatches the gun back after `arm_disarm_duration`. Leg hits apply a timed move-speed penalty. A self-kill loses the duel (SP reason `You shot yourself`). Non-fatal MP wounds sync via `DuelManager._mp_wound`. `Hitbox.region` also drives AV. Hit chunks are cosmetic and ride the same hit: `Bullet` passes the struck shape index to `Hitbox.receive_hit`, which (when `BodyChunks.roll()` passes against `chunk_chance`) asks the owner's `DummyBody.cut_at` for the cut: `BodyHitboxes.bone_of` maps the shape to a skeleton bone, and the hit is snapped onto the skin. The cut is `{bone, local, radius}` (`{}` = none), passed as `take_bullet_hit(..., cut)` and `mp_report_hit(..., cut)`; it calls `knock_chunk(cut, dir, clip_t, lethal)` after `resolve`, before the death or wound feedback. In 1v1 the host's `mp_report_hit` sends `DuelManager._mp_chunk(victim_is_host, bone, local, radius, dir, clip_t, lethal)` (reliable, ahead of `_mp_finish` / `_mp_wound`, only when the cut is non-empty) and each peer cuts its own copy of the body; gore is checked per peer. `_finish_sp` is idempotent once `RESOLUTION` is set.
- **Feedback:** `ImpactFeedback` autoload — spatial SFX (`assets/audio/`, swap via `AudioCatalog`), one-shot particles (`assets/vfx/`), XR rumble + flat joy vibration (`assets/haptics/`). Cue checklist and placeholder vs real status: [`SOUND.md`](SOUND.md). `GameManager.setup` shows `ui/loading_screen.tscn` (and a VR HMD cover) and awaits `warmup()` before `go_to_menu()`. That precaches audio PCM and draws a camera-parented copy of muzzle/impact/glass/coin particles, a live `BulletTrail`, the slug mesh, a muzzle OmniLight, and muted gunshot / impact / glass cues so the first live round does not compile those pipelines. The host is small but not 0.001-scale (Compatibility culls that).
- **Kill cam:** `DuelManager.kill_cam_requested(trail_points)` → `KillCam` (SP and 1v1 MP). Flat: cinematic fly-along `Camera3D`. VR: spectator `XROrigin3D` ride (player rig stays put) + `XRToolsFade`. `TimeManager.notify_kill_cam` burst allowed in MP; other slow-mo stays SP. Lethal sting: `AudioCatalog` `&"duel_end"` on `notify_kill_shot`. On a lethal hit the camera is handed to `DeathCam` instead of restoring first person.
- **Hit volumes:** `BodyHitboxes` (child of `DummyBody`, `HITBOX_PRIORITY` 40, after arm IK and fingers) owns the shapes of six `Hitbox` areas per combatant: head sphere on `Head`, a torso capsule hips to neck, per-arm upper-arm and forearm capsules (stop at the wrist bone), per-leg thigh and shin capsules (shin reaches the sole). Scenes carry empty `Hitbox` areas; `DummyBody.attach_hitboxes` builds the shapes at spawn. Player, remote avatar, and NPC all call it, so nods, IK reach, and the step move the volumes. Corpse volumes keep following the posed (or replayed) bones; the NPC switches its volumes off in `_die`. F3 **Show hitboxes** (`DebugMenu.show_hitboxes`, `Hitbox.set_debug_visible`) draws them (the local head volume is skipped). In 1v1 the host's remote avatar rebuilds the peer's body from the pose stream, so a hit is judged on that copy.
- **Player body:** `characters/dummy_body.gd` instances `dummy.glb` on the local player, the remote avatar, and AI. While the local player is alive in flat mode the mesh stands on the floor under the head. In VR that body is hidden for now and only the hand triangles show, at the imported mesh size; the corpse orbit shows the full mesh again. Neck and head nod with camera pitch (about ±35°). Spine, chest, and hips stay in the rest pose. Both legs take an in-place step from horizontal travel (`DummyBody.follow_travel`): the local rig origin, the duelist root, the remote head, or the mesh-lab puppet. About 0.8 m is one cycle. Under about 0.35 m/s the swing eases out, and a jump over 1.5 m in one frame is ignored. The local VR body stays shelved, so the headset still shows only the hands; the remote avatar is not shelved, so the other player sees the step. The body stands on the floor under the head. Flat and VR both only nod the neck. VR wrists IK to the posed shoulder. The imported arm stays at its Blender size (about 46 cm, with a 4 cm-wide hand) and, past that length, the upper arm and forearm scale along the bone so the mesh reaches the controller. Flat wrists hang at the side, or reach the held revolver and an in-hand off-hand prop. The hand rolls and bends off the forearm to follow the target (about 60°), and a short inset puts the palm on the grip. Finger bones (`Thumb`, `Index`, `Middle`, `Ring`, `Pinky`, two each) blend in `characters/hand_fingers.gd` after that IK. VR closes on the grab button: a fist if the hand is empty, otherwise the pose for what it is holding. Flat stays open until that hand is holding something. The wrist target lerps onto a `GripAnchor` marker on the held visual over about 100 ms (marker `-Z` is the finger direction). Ocelot spin keeps the wrist on the controller and leaves the pistol curl. The index blends toward `PistolTrigger` with the trigger pull. The VR hand slice includes every bone under `Hand.L` / `Hand.R`, so the fingertips stay visible while the body is shelved. Triangles weighted to `Head` are hidden on the local body until death (`set_head_hidden`). `dummy.glb` is one `M_Dummy` surface. `DummyBody._split_parts` splits it once (cached per source mesh) into body, head, and hand parts shared by every body, and keeps each bone's rest triangles (those it dominates) for the skin snap. A hit cuts a hole where the bullet landed, at runtime, on any skinned mesh; the mesh is never rebuilt. `DummyBody.cut_at(shape, point, shot, region)` finds the bone (`BodyHitboxes.bone_of`), `cut_on_bone` snaps the point onto that bone's posed skin (the shot cast against its rest triangles in bind space), rolls the radius from `cut_min..cut_max` (5-10 cm, arms and legs capped at `cut_limb_max`, 6 cm), and lifts the sphere center `BodyChunks.CUT_LIFT` of the radius out against the shot. The cut stores that center in the bone's pose space, so it rides the pose, the ragdoll, and the replay. Rendering is two shaders on one `ShaderMaterial` per body (`BodyChunks.skin_material_new`, shared by its body and head parts; hands keep the solid material, so they are never cut): `characters/body_skin.gdshader` holds the albedo, the first-person clip, and `holes[8]` / `hole_count` (world centers and radii); a fragment inside any sphere is discarded and the ring just outside it is stained red. `characters/body_cavity.gdshader` is its `next_pass` (back faces only), attached only while the body has holes, and draws the bowl floor and red-to-dark walls through the cut, writing depth so the cavity never shows daylight through the body. It also gets `hole_lifts[8]` / `cut_lift`, a lift plane from the shot direction stored in bone space per event, so the bowl floor does not draw in front of the skin at grazing angles or in shadows. `BodyChunks` (`characters/body_chunks.gd`, child of `DummyBody`, process priority 45) keeps the events `{cut, lift, t, gib, out, replayed}`; the newest `HOLE_CAP` (8) that are out show, and the ninth heals the oldest. Each frame it converts the active cuts to world centers for the uniforms. A knock (`knock_chunk`) records the event, `flesh_chunk` plays, and a `BodyGib` (`characters/body_gib.gd`, a `RigidBody3D` that collides with the world only) is thrown along the shot at `gib_speed`: one of 3 procedural lumps (skin dome plus jagged flesh underside, built once), scaled to the cut radius. A gib keeps a 30 Hz world-space track and freezes when it settles by the ragdoll's rule. It lives under the scenario, so a new duel, the menu, practice, or the mesh lab frees it; a horde wave does not. At most `gib_cap` gibs live at once (the oldest goes first; below 1 there are none). Gore off heals every hole and frees all gibs. A killing hit spawns a gib even on the shelved VR body; a non-lethal hit there only records the hole. `Player.reset_for_wave` heals the holes and leaves the gibs. `set_pose_driven(false)` on the lethal hit stops the neck, arm, and leg writers. Replay turns them back on for the clip, then `freeze_replay_body` stops them again so the orbit still holds the death pose. A killing shot then calls `DummyBody.collapse(trail)`: `characters/body_ragdoll.gd` (child at process priority 35, between the fingers and the hit volumes) builds 12 `RigidBody3D` capsules on `ConeTwistJoint3D` / `HingeJoint3D` from the posed bones (radii from `BodyHitboxes`, bone pose scale reset first because arm IK stretches it) and writes the bones back parent-first from the bodies, interpolated by `Engine.get_physics_interpolation_fraction()`. Physics keeps its real tick rate under slow-mo and scales the step instead (the track and the settle timer run on that scaled game time), so the cone joints use a low `CONE_BIAS`; at the engine default the limits blow the body apart when the step grows back. It is plain rigid bodies, not `PhysicalBoneSimulator3D`, for the same reason `dummy_arm_ik.gd` runs in `_process`. Bodies sit on physics layer 8 `ragdoll` and mask only the world. The last trail segment gives the shot: the body nearest the hit point takes `ragdoll_hit_impulse`, and hips / spine / chest share `ragdoll_torso_push` with `ragdoll_lift` of it going up (the impulse waits one physics step, because a new body has no mass properties before its first step). When every body is slower than `ragdoll_settle_speed` for 0.4 s, or after `ragdoll_max_time`, the pose is baked, the bodies and joints are freed, and the corpse is held. While a corpse owns the skeleton `set_pose_driven(true)` is ignored; `release_corpse()` (called from `Player.reset_for_duel`) resets every bone and unlocks. A 30 Hz track of the 12 bone poses is kept for the replay. Callers: `DuelistAI._die` (the old tip-over tween is the `ragdoll_enabled` 0 fallback), `Player.take_bullet_hit` in single player, and `DuelManager._mp_finish` for the local victim (`Player.collapse`) or the remote victim (`RemoteAvatar.collapse`) only when the kill has a trail. Fouls never collapse. The gun drops with `release_into_world(..., keep_hinge=false)` and the off-hand prop with `drop_loose` (`PropController.drop_on_death`). Mesh lab key 4 shoots the puppet from the fly camera. Mesh lab key 5 knocks the next chunk spot toward the fly camera.
- **Death cam + replay:** `ReplayBuffer` records 30 Hz poses and shots from standoff (SP and the 1v1 host). A lethal hit keeps `replay_post_death` seconds and the host RPCs the sealed clip. Fly-along and playback lock both fighters. The corpse orbit (`death_cam_hold`, and again after the clip) is only the dead player's camera; the winner keeps control. Playback is the killer's recorded head until `death_time` (the `duel_end` sting plays again, full speed), then that same orbit for the rest of the clip. The local victim's mannequin follows that clip: `apply_replay_pose` turns the pose writers back on and places the head, both arms, and the in-place step (a travel marker, so VR legs move while the rig stays put). The gun hand meets the revolver grip when the flags say it is held. The revolver itself is pinned to the recorded pose, including an open gate and the cylinder index, so a toss or a spin does not keep simulating. An off-hand prop and a held reload round are ghosted from the same samples (`player/replay_objects.gd`); the live copies stay put until the clip ends. Voice and scenery are not rewound. After the clip, `freeze_replay_body` stops those writers so the corpse orbit holds the death pose. The orbit pivot is `corpse_body().corpse_pivot()`, the fallen chest. At playback start `corpse_replay_begin()` cuts a fall that is still running short and gives the skeleton back to the pose writers, so the body stands for the clip before the death; from `death_time` on `corpse_replay_at(t - death_time)` plays the recorded fall on the clip clock (slowed with the tail), and `corpse_hold_final()` ends on the settled pose. The latched player clip keeps refreshing the gun and the off-hand prop from the live pose so they fall in the clip. AI and the remote avatar apply the same joints. A REPLAY tag sits in the corner for the clip (flat HUD; `Label3D` on the headset camera in VR) (last `replay_slow_seconds` at `replay_slow_factor` on the playback clock only). Either peer's fire/trigger skips the clip. The trailing orbit starts the existing menu / gauntlet / rematch delays. Fouls (empty trail) skip the whole sequence. With several NPCs (SP only) the buffer records `actor_count()` actors (the player plus each NPC; MP and 1v1 stay at 2, and the pack/unpack stride stays at `ACTORS`), and `death_times` maps an actor id to its clip time (`note_death`, `death_time_of`). Hit chunks use the same clock: `knock_chunk` stamps `ReplayBuffer.clip_time()` (or -1 outside a recording). At playback start `chunks_replay_begin` heals every hole cut inside the clip and hides its gib; `chunks_replay_at(t)` opens each at its time and re-flies the gib's track, on every actor including the killer; the trailing orbit holds them all open (`chunks_hold_final`). A hole from before the clip stays open. A mid-fight NPC death is a ragdoll at normal speed with no kill cam; only the final death (a win) or the player's death starts the sequence. In playback the victim and every NPC that died inside the clip (`DeathCam._retraced`) stand up, then play their own fall at their own death time and are held again on the trailing orbit; an NPC that died before the clip began stays a corpse. With more than two actors `_unlock_winner` frees the gun of every living actor but the victim. After a loss the survivors stay frozen through the fly-along, hold, and replay, then fight each other on the trailing orbit until the usual delay leaves the scene.

## AI

- Data-driven `AIArchetype` resources (reaction, accuracy cone, draw speed, `reload_time`, movement). The visible body is the same mannequin; archetype `body_color` tints it. While the revolver is held, the gun arm IK aims at the revolver `GripAnchor` and the hand plays the pistol pose; the index curls on the shot. Greybox body meshes stay hidden.
- After 6 shots the AI enters `RELOADING`: gate opens (cylinder rolls out), arm dips, waits `reload_time / ai_speed_mult`, then `WeaponBase.fill_cylinder()` + `close_gate()` and resumes fire. Arm hit / death / duel-over close the gate without refilling. SP only.
- SP spawn: `GameManager._begin_ai_duel(scenario, lineup, health_mult)` instantiates one `ai/duelist.tscn` per lineup entry into `GameManager.current_ais` (slot *i* is `actor_id` *i + 1*; the player is 0), places it on `ScenarioBase.get_enemy_spawns(count)`, then `DuelistAI.capture_spawn()` (`global_position`). Do not snapshot position in `_ready` — that runs at packed-scene origin before placement. Sheriff/Ghost strafe around that captured origin; Drunk stands. One NPC uses `EnemySpawn`. Two or three read the `Marker3D` children of `EnemySpawns2` / `EnemySpawns3` in the scenario scene; only their positions are authored, and each yaw is derived to face the lane center. `strafe_half_width` on the scenario (Train Rooftop 1.5) clamps a strafer's world X; 0 is no clamp. Free-duel lineups come from `start_free_duel(scenario, archetype_index, count)`; an index equal to `ARCHETYPES.size()` is Mixed (each slot rolls). A second or third copy of one archetype gets `NPC_TINT_SHIFT` lighter or darker `body_color`.
- Multi-NPC targeting (free-for-all): with one NPC the target is the player, set before the bell. With two or three, each NPC picks a random live duelist (`GameManager.live_duelists()`: the player or another NPC) in `begin_draw`, retaliates against the shooter of a non-lethal hit, and re-picks when its target dies; with no rival left it stands down. `DuelManager._on_enemy_died(trail, ai)` shows `N left` while any NPC lives, and the last death runs `notify_kill_shot` with `ai.killed_by` (the real shooter) and ends in `Last one standing`. The enemy-draw slow-mo fires once, on the first NPC draw. After a player death with two or more NPCs alive, `survivors_fighting()` unfreezes them during the trailing orbit.
- Encounter ladder: `DuelEncounter` + `GauntletLadder` `.tres` files — prefer data over code for new rungs.

## Horde mode

- `HordeController` (`gauntlet/horde_controller.gd`) sits beside `GauntletController` as a `GameManager` child; `DuelManager` stays the per-wave state machine, with small hooks (below) rather than a parallel one. `GameManager.start_horde(scenario_index)` loads the arena once (one time-of-day for the whole run) and calls `horde.start(load(HORDE_WAVES))`, which starts wave 1.
- Wave data: `HordeWaves` (`gauntlet/horde_waves.gd`) reuses the gauntlet rung type (`DuelEncounter.lineup()`) for `waves`, an array ordered weakest → strongest. `lineup_for(wave)` picks `waves[(wave-1) % waves.size()]` and, after a full loop through the table, promotes every slot one archetype tier along `GameManager.ARCHETYPES` (capped at the last tier); `speed_for(wave)` adds `loop_speed_step` per loop. `gauntlet/horde_default.tres` authors 8 waves.
- Each wave: `GameManager.begin_horde_wave(lineup, speed_mult, wave)` calls `_clear_combatants()` (frees the last wave's corpses/bullets/trails, aborts replay/DeathCam), `local_player.reset_for_wave()` (full HP + cylinder, holster, no teleport — see below), gets spawns from `ScenarioBase.get_horde_spawns(count, avoid, min_distance)`, spawns via the shared `_spawn_npcs` helper (also used by free duel / gauntlet), sets `DuelistAI.focus_player = true` and `set_target(local_player)` on every NPC, connects each `died` signal to `HordeController.note_kill` *before* `DuelManager.start_ai_duel(..., replay_win=false)` so kill credit lands before the wave-clear handler runs.
- Focus targeting: `DuelistAI.focus_player` makes `_pick_target()` always return the player (while alive) instead of the shipped free-for-all pick, and skips the normal retaliation retarget in `take_bullet_hit`. Crossfire still lands physically — a stray hit hits whoever it hits — it is just never *chosen*. Once the player is dead, survivors fall back to the normal free-for-all pick.
- Spawn filter: `ScenarioBase.get_horde_spawns` pools `get_enemy_spawns` plus the `EnemySpawn(s)` markers at every arena, dedupes them, keeps markers at least `spawn_min_distance` (flat distance) from the player, and falls back to the single farthest marker if none qualify — so a wave never spawns zero NPCs even if the player is standing on top of every marker.
- `DuelManager.start_ai_duel(ais, lineup_text, replay_win)`: Horde passes `replay_win = false`. On the wave's last kill, `_on_enemy_died` skips `notify_kill_shot` (so `ReplayBuffer.mark_death` never runs and `DeathCam` never starts) and instead just plays the `duel_end` sting and emits `kill_cam_requested` — the fly-along and `TimeManager.notify_kill_cam` slow-mo play exactly like a duel win, with no replay or orbit after it. A loss (the player's death) is untouched: same kill cam, `DeathCam`, orbit, and replay as a free-duel loss, with survivors fighting in the trailing orbit if more than one NPC is left.
- Scoring lives on `HordeController`: `note_kill` credits `kill_points` (+`headshot_bonus`) only when `DuelistAI.killed_by == ReplayBuffer.ACTOR_HOST` (a crossfire kill still counts toward "N left" but scores 0); `clear_wave()` adds `wave_bonus * wave` and returns the "WAVE N CLEARED" banner text that `GameManager._on_duel_finished` substitutes for the usual win message. `GameManager` schedules `horde.on_duel_finished(won)` after `horde.break_seconds()` (win) or the usual 3.5 s (loss) the same way it schedules `gauntlet.on_duel_finished`.
- Between waves the player keeps position and facing: `Player.reset_for_duel` is now a thin wrapper — transform + rig reset — around `Player.reset_for_wave()` (HP, holster, cylinder, props), which Horde calls directly without touching the transform.
- Death ends the run: `HordeController._game_over()` calls `PlayerSettings.record_horde_run(waves_cleared, score)` (separate maxima for best wave and best score under `[horde]` in `user://settings.cfg`), shows a 5 s "HORDE OVER" summary, then `GameManager.go_to_menu()`.
- HUD: flat gets a persistent `Hud.HordeStatus` corner label (`set_horde_status(wave, score)`); VR relies on the existing `show_vr_message` banners (wave start / clear / game over). Pause **RESTART HORDE** routes through `GameManager.reset_current_duel()` → `start_horde(current_scenario_index)` (the scenario reloads, so the time of day re-rolls).

## Multiplayer

- Interface in `netcode/`; `enet_transport.gd` (LAN + UDP discovery), `steam_transport.gd` (optional GodotSteam GDExtension).
- **SKU split:** Meta Store / Quest APK is **LAN-only**. Steam lobbies are desktop / Steam. `NetworkManager.steam_available()` is false on Android; `ui/main_menu.gd` hides Steam host/join chrome there. No Meta dedicated-server path.
- **Steam 1v1:** `NetworkManager` inits Steam once on desktop (`steamInitEx` app ID 480, then `initRelayNetworkAccess`). GodotSteam 4.22 lives in `addons/godotsteam/` (not enabled as an editor plugin; the GDExtension loads on its own). `steam_appid.txt` + Project Settings `steam/initialization/app_id` are 480 for editor/dev; `addons/gunslinger_steam_export/` copies that file next to Windows/Linux/macOS executables. Lobby metadata: `gunslinger=1`, display name, `gunslinger_version`. Browse uses worldwide distance + that game key. Join refuses when lobby version ≠ local `application/config/version` (before `SteamMultiplayerPeer`); mismatched lobbies stay listed but disabled. `SteamMultiplayerPeer` is created with `server_relay`. Host session starts on `lobby_ready`; joiner waits until the Godot peer is `CONNECTION_CONNECTED`, then completes a version hello RPC before `session_started`. Steam invite overlay is not auto-opened on host (that stole the HOST click and stuck the dialog); pause **Invite friends** calls `activateGameOverlayInviteDialog`. Full lobby (2/2) is set unjoinable until the peer leaves. **Virtual ports rotate:** GodotSteam 4.22's `SteamMultiplayerPeer.close()` never frees its P2P listen socket, so a port is spent for the life of the process. Sessions therefore use `create_host(port)` / `create_client(owner, port)` with a port `SteamTransport._spent_virtual_ports` has not seen (0 first, then random 1–999) and the host publishes it as lobby metadata `gunslinger_port`; do **not** go back to `host_with_lobby` / `connect_to_lobby`, which hardcode port 0 and break every session after the first ([BUG-009](BUGS.md)). Because those helpers are bypassed the addon's `tracked_lobby` is unset, so `SteamTransport` handles `lobby_chat_update` itself to drop the peer when the other player leaves. Create and join are one in-flight request issued from `poll()`: a lobby arriving after the player left is left again instead of adopted, and an unanswered request fails after 10s. `close()` drops the Godot peer before leaving the lobby, and `NetworkManager.leave()` always tears the long-lived Steam transport down even when `transport` is already nuler; it does not shut Steam down. Overlay invite on host is best-effort (`activateGameOverlayInviteDialog`).
- LAN discovery (`lan_discovery.gd`): host beacon on UDP 9100 answers pings and announces `ip|name|version` on `255.255.255.255` plus subnet `.255` (legacy `ip|name` / bare name still parse with empty version). Browse list disables incompatible hosts; `join_lan` refuses when the discovery cache has a mismatched version. Typed IP with no beacon metadata relies on the handshake. Gameplay ENet is UDP 9099, bound to IPv4 `0.0.0.0`.
- **MP version handshake:** After ENet/Steam connect, the joiner sends `_version_hello`; the host does not emit `peer_joined` (and thus does not start the duel) until versions match. Mismatch → reject RPC with both strings, disconnect joiner, host session stays up. ~3s timeout treats a silent peer as an older build.
- Quest Android export: `addons/gunslinger_lan_permissions/` injects `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`, and `CHANGE_WIFI_MULTICAST_STATE` into the manifest at gradle export (also set on `export_presets.cfg`). Without `INTERNET`, `create_server` fails with "Can't create" on device. Steam Link + editor is Windows networking, not the APK. GodotSteam is excluded from the Android preset (`exclude_filter`).
- Pose / shot sync; host validates hits and HP; non-fatal wounds via `_mp_wound`; auto rematch. Gameplay slow-mo off while networked; kill-cam burst still plays after `RESOLUTION` from `_mp_finish` trail points. Pose RPC is `head, left, right, flags, gun_transform`. Flags: `GUN_DRAWN`, `GUN_COCKED`, `GUN_FREE`, `HOLSTER_LEFT`, `GUN_HELD_LEFT`, `GUN_SPINNING`, `GUN_STEADIED`. Remote interpolates a free, spinning, or aim-steadied gun; does not simulate physics.
- `RemoteAvatar` (`player/remote_avatar.tscn`): pose-driven head/hands. The visible body is the rigged mannequin (`characters/dummy_body.gd`); greybox meshes stay hidden and the hitboxes stay. Arm IK (`characters/dummy_arm_ik.gd`) puts the wrists on the tracked hands and rolls each hand with that hand's basis. While the peer revolver is held and not spinning, that wrist aims at the gun's `GripAnchor` instead. Finger pose and trigger travel in the pose packet's `hands` int (`HandFingers.pack`). The body yaws with the head and stays upright. The neck takes the look. Revolver sits on the chosen hip until drawn, parents to left or right hand (identity, or interpolated world pose while `GUN_SPINNING` or `GUN_STEADIED`), or follows the free-gun transform.
- MP spawn: host on `PlayerSpawn`, joiner on `EnemySpawn`. `reset_for_duel` copies the marker transform onto the Player root. Flat look yaw is stored local to that root (do not apply marker yaw twice). VR `reset_locomotion` yaws the origin so the HMD faces the marker -Z, then reapplies a saved standing eye height (`VRRig.apply_saved_eye_height`: `origin.position.y = saved - camera.position.y`) so the headset sits at that height above the player root. The same one-shot runs on the first tracked pose and when Settings **Reset view height** is pressed. Torso, legs, and holster stay on the floor offsets in `Player._follow_body`. Until a height is saved, the runtime floor is left alone. Flat walk and VR stick locomotion apply in world XZ (`global_position`) from look yaw so the joiner's 180° root does not invert strafe.

## Voice chat

- **Buses:** `assets/audio/default_bus_layout.tres` (project setting `audio/buses/default_bus_layout`) adds **Voice** (incoming peer, own volume slider) and **Mic** next to the existing **Master**. `Mic` is **muted** and carries an `AudioEffectCapture` — muting a bus still feeds its effects, and it is what keeps players from hearing themselves. `audio/driver/enable_input=true` is required or the mic never opens. `PlayerSettings.apply_audio()` drives Master + Voice; everything else still defaults to Master, so existing SFX are untouched.
- **Capture:** `VoiceChat` (`autoload/voice_chat.gd`) owns one `AudioStreamPlayer` with an `AudioStreamMicrophone` on the `Mic` bus. It only runs while a session is live **or** Settings is on screen (`add_monitor` / `remove_monitor` refcount, so the mic is not held open for the whole process just to draw a level bar). `is_available()` is a pure query (headless / `Dummy` driver / missing bus / ungranted Android permission) — it never prompts, because the UI and debug panel poll it.
- **Codec:** driver-rate stereo frames are downmixed and box-averaged to **16 kHz mono PCM16**, 320 samples (20 ms, 640 B) per packet, then a one-pole **180 Hz high-pass** (rumble / fan thump) and a squared-ratio expander below the noise-gate cutoff. Cheap: one extra multiply per 16 kHz sample.
- **Gating:** mute always wins. With push-to-talk **on**, the bind is the whole gate (the expander still ducks room tone while you hold it). With it **off**, RMS must clear Settings **Noise Gate** (`PlayerSettings.voice_gate_cutoff`, default 0.08, same units as the mic-level bar) plus a 0.18 s hang so word tails survive. 0 disables the gate. Raise the slider until the bar sits still when you are quiet.
- **Latency:** capture discards everything but the newest 40 ms after a hitch (WASAPI can otherwise dump seconds of backlog). Incoming packets sit in a 2-deep queue that drops the oldest on overflow, and playback is capped around 40–80 ms. `_voice` is `@rpc(..., "unreliable", 2)` and `_voice_state` uses channel 1, so a reliable shot on channel 0 cannot stall the mic for seconds. ENet's default `channel_count` is already 3 (0..2).
- **Spatial playback + mute X:** `RemoteAvatar/Head/MouthMarker` holds `VoicePlayer` (`AudioStreamPlayer3D`, `Voice` bus, `voice_max_distance` / `voice_unit_size` from `GameManager.tuning`) and `MuteX` (billboard `Label3D`). `GameManager._spawn_avatar` / `_despawn_avatar` call `VoiceChat.bind_voice_player()`. Mute state travels on pose flag `POSE_FLAG_VOICE_MUTED` (30 Hz steady state) plus a reliable `_voice_state` RPC that covers the gap between `peer_joined` and the first pose; both land on `RemoteAvatar.set_voice_muted()`.
- **Binds:** flat `voice_mute` (**M**) and `voice_ptt` (**V**) are ordinary `FLAT_ACTIONS` rows, so they remap and persist like combat keys. VR is deliberately **not** in the bind table: all six `VR_SOURCES` are already combat binds, so a VR voice bind could only be bought by unbinding a combat button. VR is always-on plus the Settings mute toggle.
- **Quest:** `RECORD_AUDIO` is injected by `addons/gunslinger_lan_permissions/` (the export dialog rewrites the checkboxes, same reason as `INTERNET`). `VoiceChat` calls `OS.request_permissions()` once and retries capture every second, so granting the prompt mid-session starts voice without a restart.

- **Slot machine:** `practice/slot_machine.gd` (`StaticBody3D` on layer 1, front faces local +Z). `pull()` returns false while spinning. Reels tick `SYMBOLS` and stop at `REEL_STOPS`. The result is rolled on pull (`WIN_CHANCE` 12% for three of a kind, otherwise a guaranteed miss). A win flashes the topper and plays `ImpactFeedback.slot_win` (coin burst + sting). VR: trigger with the hand within `LEVER_REACH` of the lever segment pulls it and does not fire. Flat: F while `is_looked_at` hits the cabinet.
- **Tutorial board:** `practice/tutorial_board.tscn` on the porch back wall (flush with `PorchWall` at z = 5.5). The `Label3D` is yawed 180° so the readable face points at the porch. `TutorialBoard` rebuilds the copy on `_ready` and `PlayerSettings.binds_changed`, branching on `GameManager.is_vr`. Bind strings come from `flat_event_label` / `vr_source_label`; `interact` is read from `InputMap` (not remappable). Jam line is omitted in VR.
- **AV:** VFX `glass_shatter` / `coin_burst` in `VfxCatalog`; placeholder cues `glass_break`, `slot_pull`, `slot_stop`, `slot_win` in `AudioCatalog` / `PlaceholderAudio`.

## UI text / translations

- Player-facing text lives in `translations/translations.csv` (`keys,en`; keys are `AREA_NAME`: `UI_`, `LOADING_`, `MENU_`, `PAUSE_`, `SETTINGS_`, `BIND_`, `HUD_`, `RADIAL_`, `RELOAD_`, `MSG_`, `NET_`, `BOARD_`, `SLOT_`). Godot imports it to `translations.en.translation`, registered in `project.godot` (`internationalization/locale/translations`, fallback `en`). Re-run the editor import (`--headless --import`) after editing the CSV.
- Scene `text` / `placeholder_text` / `tooltip_text` hold the key (Controls and `Label3D` auto-translate). Code uses `tr("KEY")`. Composed strings are format keys: `tr("MSG_NPCS_LEFT") % left`. Duel result reasons travel as `MSG_REASON_*` keys (also over the MP RPC) and `GameManager._on_duel_finished` translates them per peer. Bind names in `PlayerSettings` label tables are keys run through `tr()`.
- Literal on purpose: NPC `display_name`, arena names, gauntlet rungs, prop wedge names, Steam names, slot reel symbols, F3 debug UI, mesh lab, version string, numeric values.
- Locale: Godot picks the OS / Quest locale; `PlayerSettings.language` (`[general] language` in `settings.cfg`) overrides it. The Settings Language dropdown is not built until the CSV gains a second locale column. No fallback font for non-Latin scripts yet.
